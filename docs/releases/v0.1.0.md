# goscrapling v0.1.0 Release Notes

Date: 2026-05-20
Target tag: `v0.1.0`

## Summary

`v0.1.0` is the first release candidate for goscrapling's tested foundation: a
Go-native web extraction engine inspired by Scrapling for agent runtimes and
single-binary Go deployments.

This release is useful for parser, selector, adaptive storage, response, static
fetcher, browser-seam, spider-foundation, CLI, and Gormes integration work. It
is not a complete Scrapling port and is not a drop-in replacement for Scrapling.

## Release highlights

- Static parsing and selectors: CSS, XPath, pseudo-element extraction, regex,
  JSON, traversal, filtering, text search, and similar-element helpers.
- Adaptive relocation: in-memory, file, and SQLite stores plus deterministic
  relocation, diagnostics, and CSS adaptive selector modes.
- Response and fetchers: HTTP response metadata, cookies, history, body helpers,
  `GET`/`POST`/`PUT`/`DELETE`, sessions, request options, retries, redirects,
  timeout, TLS verify control, explicit proxy options, and opt-in safety gates.
- Browser foundation: engine-neutral browser fetcher, chromedp JavaScript
  fixture, rendered markdown, and semantic tree extraction.
- Spider foundation: request/result/session/scheduler contracts, follow flow,
  duplicate filtering, allowed-domain filtering, concurrency, and domain delay.
- CLI: static `extract get/post/put/delete`, local binary E2E coverage, and
  opt-in robots-gated live practice-site E2E.
- Integration: Gormes browser extraction tools and cross-layer local E2E proof.
- Governance: progress ledger, feature map, coverage ledger, generated builder
  queue, and repo-local workflow skills.

## Compatibility and requirements

- Module path: `github.com/TrebuchetDynamics/goscrapling`
- Go directive: `go 1.26`
- Upstream parity oracle: D4Vinci/Scrapling observed at commit
  `6380ef0f266a5fff898c18953d6b03ca320b2fd4`, release `v0.4.8`.

## Known gaps

The project remains partial. Major planned work includes selector generation,
proxy rotation strategies, concurrent fetcher APIs, deeper browser sessions and
page lifecycle behavior, browser waits/actions/screenshots/downloads/XHR,
stealth boundaries, spider robots/cache/checkpoints/retries/streaming/templates,
advanced CLI modes, MCP server, examples, benchmarks, and parity scorecards.

## Validation checklist

Run from a clean checkout before tagging:

```sh
go test ./... -count=1
go test ./cmd/goscrapling -count=1 -v
go run ./cmd/progress validate
jq empty docs/content/building-goscrapling/architecture_plan/progress.json
git diff --check
```

Optional live E2E validation:

```sh
GOSCRAPLING_LIVE_E2E=1 go test ./cmd/goscrapling -run TestLivePracticeSitesEndToEnd -count=1 -timeout 10m
```

## Tagging instructions

After the release-prep commit is merged and validation passes:

```sh
git tag -a v0.1.0 -m "goscrapling v0.1.0"
git push origin v0.1.0
```

Do not tag a dirty tree. Do not tag if release validation fails.
