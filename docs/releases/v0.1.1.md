# goscrapling v0.1.1 Release Notes

Date: 2026-05-20
Target tag: `v0.1.1`

## Summary

`v0.1.1` is a maintenance release for goscrapling's `v0.1` line. It keeps the
project positioned as a partial Go-native Scrapling-style feature port and does
not claim new complete Scrapling parity.

This release prepares the codebase for the next spider, browser evidence, and
CLI slices by deepening internal seams while preserving public behavior.

## Release highlights

- Spider runtime: `spiders.Crawler.Run` now delegates orchestration to a private
  crawl runtime, keeping scheduler, limits, sleep, task-result collection, and
  active-task accounting out of the public runner method.
- Browser evidence: markdown, semantic nodes, links, structured data, and
  interactive element extraction now share one rendered evidence module instead
  of duplicating HTML parsing and traversal across browser and Gormes adapters.
- CLI extract command: static `goscrapling extract get/post/put/delete` now uses
  an internal extraction plan seam for parse, request planning, execution,
  rendering, and file writing.

## Compatibility and requirements

- Module path: `github.com/TrebuchetDynamics/goscrapling`
- Go directive: `go 1.26`
- Upstream parity oracle: D4Vinci/Scrapling observed at commit
  `6380ef0f266a5fff898c18953d6b03ca320b2fd4`, release `v0.4.8`.

## Public behavior

No intentional public API or CLI behavior changes are included in this release.
The refactors are internal architecture deepening to reduce drift before future
Scrapling-parity rows.

## Known gaps

The project remains partial. Major planned work still includes selector
generation, proxy rotation strategies, concurrent fetcher APIs, deeper browser
sessions and page lifecycle behavior, browser waits/actions/screenshots/
downloads/XHR, stealth boundaries, spider robots/cache/checkpoints/retries/
streaming/templates, advanced CLI modes, MCP server, examples, benchmarks, and
parity scorecards.

## Validation checklist

Run from a clean checkout before tagging:

```sh
go test ./... -count=1
go run ./cmd/progress validate
jq empty docs/content/building-goscrapling/architecture_plan/progress.json
git diff --check
```

Optional live E2E validation:

```sh
GOSCRAPLING_LIVE_E2E=1 go test ./cmd/goscrapling -run TestLivePracticeSitesEndToEnd -count=1 -timeout 10m
```

## Tagging instructions

After the release-prep commit is merged and validation passes:

```sh
git tag -a v0.1.1 -m "goscrapling v0.1.1"
git push origin v0.1.1
```

Do not tag a dirty tree. Do not tag if release validation fails.
