# goscrapling v0.1.2 Release Notes

Date: 2026-06-01
Target tag: `v0.1.2`

## Summary

`v0.1.2` is a patch release for goscrapling's `v0.1` line. It keeps the
project positioned as a partial Go-native Scrapling-style feature port and does
not claim complete Scrapling parity.

This release packages the recent hermetic parity work across browser fetchers,
spiders, CLI shell behavior, MCP/Gormes integrations, and the generated builder
control plane so downstream Go users can consume a stable tagged module through
GitHub and pkg.go.dev.

## Release highlights

- CLI shell parity: scripted `goscrapling shell -c` now covers static
  `get/post/put/delete` shortcuts, `help()`, `pages` history inspection, curl
  conversion helpers, and a bounded `view(page)`/`view(response)` artifact
  writer that does not launch a browser in tests.
- Browser and integration surfaces: browser sessions, page-pool lifecycle,
  wait/action/capture controls, context/resource options, stealth boundaries,
  rendered markdown, semantic trees, Gormes browser tools, and MCP-style tool
  handlers are fixture-backed.
- Spider runtime: robots, response cache, checkpointing, blocked-response retry
  hooks, lifecycle/stat/export behavior, link extraction, crawl/sitemap
  templates, and static/browser/stealth/proxy session adapter seams are covered
  by local tests.
- Static fetcher and response surfaces: proxy rotation, fetch safety controls,
  bounded concurrent fetching, identity/HTTP3 unsupported boundaries, and
  response metadata helpers are represented in tested Go APIs.
- Release and parity control plane: progress rows, upstream coverage ledgers,
  builder queues, parity matrix, app-map surfaces, benchmark fixtures, and
  scorecard generation were refreshed after the folder/package topology work.

## Compatibility and requirements

- Module path: `github.com/TrebuchetDynamics/goscrapling`
- Go directive: `go 1.26`
- Upstream parity oracle: D4Vinci/Scrapling observed at commit
  `6380ef0f266a5fff898c18953d6b03ca320b2fd4`, release `v0.4.8`.

## Public behavior

This release adds visible CLI shell behavior and many fixture-backed parity
surfaces. The package remains pre-`v1`; public APIs should still be treated as
subject to refinement while Scrapling parity work continues.

## Known gaps

The project remains partial. The current builder queue keeps a narrow shell
browser shortcut boundary row ready for follow-up work, plus an umbrella for
future upstream release deltas and unclassified surfaces. Full Python/IPython
REPL compatibility, arbitrary shell expressions, live browser deployment
expectations, and any challenge-solving or anti-bot bypass claims remain out of
scope unless a future row adds explicit tests and operator-visible controls.

## Validation checklist

Run from a clean checkout before tagging:

```sh
go test ./... -count=1
go run ./cmd/progress validate
jq empty docs/content/building-goscrapling/architecture_plan/progress.json
git diff --check
```

Optional live E2E validation, only when live network access and robots.txt
preflight are acceptable:

```sh
GOSCRAPLING_LIVE_E2E=1 go test ./cmd/goscrapling/live/e2e -run TestLivePracticeSitesEndToEnd -count=1 -timeout 10m
```

## Tagging instructions

After the release-prep commit is merged and validation passes:

```sh
git tag -a v0.1.2 -m "goscrapling v0.1.2"
git push origin v0.1.2
```

Do not tag a dirty tree. Do not tag if release validation fails.
